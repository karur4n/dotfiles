# Obsidian vault を探す

vault はユーザーの knowledge base。答えや前提を自分の推測で埋める前に、ここに書いてないかを探す。見つからなければ「vault には無かった」と言ってから進める。

```bash
V=~/Library/Mobile\ Documents/iCloud~md~obsidian/Documents/Obsidian_Vault
```

## 探し方

1 回で当てようとせず、語を変えて何度か引き、当たったノートを読み、そこから出ているリンクをたどる。

| 引き方 | コマンド |
|---|---|
| ファイル名 | `rg --files -g '*.md' "$V" \| rg -i '<語>'` |
| 本文（どのノートに出るか） | `rg -l -i '<語>' -g '*.md' "$V"` |
| 本文（前後の文脈） | `rg -n -i -C2 '<語>' -g '*.md' "$V"` |
| 2 語とも含む | `rg -l -i '<語1>' -g '*.md' "$V" -0 \| xargs -0 rg -l -i '<語2>'` |
| このノートを指すノート | `rg -l '\[\[<ノート名>' -g '*.md' "$V"` |
| 主題で絞る | `rg -l '"\[\[<主題>\]\]"' -g '*.md' "$V"`（frontmatter の topics は引用符付き） |

- 語は表記を変えて引く: 日本語と英語（入金サイクル / deposit cycle）、テーブル名・関数名・PR 番号・PAY-xxxx、人名は姓だけでも
- 当たりが多いときは、ファイル名と見出し（`rg -n '^#' <file>`）を見てから読むものを選ぶ
- 新しい日付のノートほど今の状態に近い。食い違ったら新しいほうを信じ、古いほうは「当時」として扱う

## 置き場所

| 場所 | 中身 | 扱い |
|---|---|---|
| 直下 | 人物・用語・知識のノート | まずここ |
| `500_プロジェクト/` | プロジェクトごとの決定・調査 | まずここ。`0. アーカイブ/` は終わったもの |
| `000_デイリー/` `001_Weekly/` | 日々の記録 | いつ何があったかを知りたいとき |
| `400_raw/` | 取り込んだ素材（議事録・記事・PR サマリー） | 元の発言や数字を確かめるとき |
| `100_Inbox/` `Tasks/` | 走り書き・タスク | 最後に |

人物の表記は直下の `<氏名>.md`、音声入力の聞き間違いは `文字起こし 辞書.md` が正。人に見せる文章を書く前に `AI に使ってほしくない言葉.md` を読み直し、挙がっている語を使わない。

## 注意

- vault は git 管理外で iCloud 同期する。読むのは自由。書くとほかの端末の編集とぶつかることがあるので、書くのはユーザーが頼んだときだけ
- iCloud の vault はファイル名が NFD のことがある。日本語のファイル名で当たらないときは本文検索で探す。Edit が失敗したら Python で書く
- frontmatter の規約は `Vault frontmatter 仕様.md` が正。点検は `cd ~/ghq/github.com/karur4n/obsidian-vault-ops && bun run frontmatter-lint`
